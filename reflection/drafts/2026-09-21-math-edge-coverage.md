# Candidate retrospective: numeric-edge coverage audit

- Evidence: the 2026-09-21 audit found happy-path synthetic tests for the recent geophone and localization math, while NaN/Inf inputs, integer-size overflow, non-finite quality/weights, invalid grid bounds, and impossible geometry cases are not systematically exercised. Bluetooth Channel Sounding tests stop at adapter/source-contract/build evidence and do not execute `cs_de_calc()` or physical ranging.
- Root cause: recent feature commits added contract tests and representative synthetic vectors, but no shared adversarial numeric-input matrix or target/HIL acceptance gate was added.
- Recurrence count: 1 confirmed episode in this repository audit; not yet enough evidence for a generalized repository-wide rule.
- Proposed minimal rule: every new math backend adds finite/overflow/boundary rejection tests and every vendor-delegated estimator gets a separate target/HIL calibration test plan; keep build, native, target, HIL, and physical evidence labels distinct.
- Affected work: geophone event picking, localization semblance/traveltime/energy/comparison, nRF geometry, and nRF Channel Sounding pair runtime added or changed 2026-09-17 through 2026-09-21.
- Follow-up correction: the first focused edge run exposed a stale impulse in a newly added SNR fixture; the fixture was reset and the corrected 8/8 run plus ASan/UBSan 8/8 run passed. This is a test-fixture correction, not a second production coverage episode, so the recurrence count for the root cause remains 1.
- Follow-up verification miss: the first post-change full All run failed one Python contract because a raw substring assertion treated the validation expression `jitter_us == INT64_MIN` as an assignment. Root cause: the contract test did not distinguish assignment syntax from equality comparison. Recurrence count: 1 confirmed episode. Proposed minimal rule: source-contract tests must match token boundaries or parse the relevant syntax instead of rejecting raw substrings. Affected work: `tests/python/test_localization_timing_budget_contract.py` in this audit; the corrected contract passed 3/3 and the final full suite passed.
- Follow-up nRF coverage audit: the user correctly questioned the small visible `nRF54L15/test` surface. Evidence: one native PlatformIO suite has 2 tests, `coverage-nrf` has 20 host suites, 109 Python nRF contract tests pass, but 6 of 24 production C files are absent from the host manifest and the canonical NCS test step is skipped. Root cause: the repository has broad host/contract coverage but no reviewed NCS-native software runner or target/HIL suite for Zephyr adapters and the Channel Sounding runtime. Recurrence count: 1 confirmed evidence gap in this audit. Proposed minimal rule: every production nRF runtime slice must have either an executable host seam or reviewed NCS-native test, while board/CS accuracy remains a separate explicit HIL gate. Affected work: `nRF54L15/src/nrf_cs_pair_runtime_zephyr.c`, Zephyr sensor bridges, and `nRF54L15/test`.
