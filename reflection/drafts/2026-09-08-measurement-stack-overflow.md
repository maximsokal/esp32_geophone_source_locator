# Candidate retrospective: measurement-service stack overflow

- Episode: the first host rerun after adding the production HWM safety-margin macro failed because the host `app_task_config.h` stub did not define that macro; the new cleanup test also exposed a missing `ESP_ERR_INVALID_STATE` test-stub definition. The corrected rerun passed 21/21.
- Separate rework: the first HIL runner draft used `recording_start/recording_stop`, which bypass the measurement-service queue. Inspection of `web_api_control.c` showed that this would not exercise the reported task. The runner was changed to dedicated `measurement_start/measurement_stop` actions routed through `measurement_service_start_async()` and `measurement_service_stop_async()`.
- Root cause of the firmware incident: the recent `a40839c` START-path restructuring kept session setup, metadata generation, and storage/FatFS calls on the measurement-service call path; the 4096-byte task then entered nested stdio/FatFS/cJSON/storage frames with large path locals. The current fix doubles the task to 8192 bytes and moves the non-realtime temporary profile/path buffers to heap with cleanup on every error path.
- Recurrence count: 1 confirmed host-stub drift episode and 1 confirmed HIL-path mismatch episode in this task. No generalized AGENTS/skill/tool rule is proposed yet; wait for a second confirmed occurrence.
- Minimal future safeguard candidate: add a compile-time host-stub contract check for production config macros and require HIL runners to identify the exact production queue/API path they exercise before accepting them as target evidence.
